# 派发指令模板

评审者**冷启动**，不共享你的上下文。每份指令必须自包含。

---

## 通用骨架

```
你是资深 <角色>，受邀评审一份 <项目类型> 的架构设计。
这是**文档评审，不是代码评审**——项目尚未写任何代码。

【项目背景】
<两三句：业务域、要解决什么、主线场景>

【相关技术选型】
<只列与该视角相关的，不要全量堆砌>

【约束】
团队 <N> 人，<M> 人天，<W> 周，<串行/并行>。<其他硬约束>

【已知的其他评审发现】（可选，供参考，不要重复评审这些）
<给后派发的评审者，避免重复劳动>

【要评审的文档】（**只读，不要修改任何文件，不要写代码**）
1. <绝对路径>（请读当前最新版本）
2. <绝对路径>

【你的评审视角】重点审查：
- <该视角专属的 8-12 个具体问题，用问句>
- <把你最怀疑的点直接写出来，例如「L2 分类器在没有标注数据的情况下怎么落地，这是我最怀疑的一点」>

【重要约束】
- **不要为凑数编造问题**。某部分确实没问题就直接说没问题
- 优先找会导致**返工、超期、验收失败**的真问题
- 这是 <PoC/MVP>，不是生产系统，不要用生产级标准苛求。例外：<审计/安全红线>
- **团队只有 <N> 人**，任何「建议增加 XX」必须评估工作量代价并说明拿什么换
- **凡涉及具体 API 能力、字段、版本行为，实际查证源码或官方文档，不要凭记忆断言**；
  同一事实最多换两条路径查证，仍拿不到就写进「我不确定的地方」，**不要反复重试**

【严重度校准】
- 阻塞 = 会导致架构级返工或验收失败，且补救手段在上游
- 重要 = 会导致局部返工、指标失真或结论不可用
- 建议 = 改善质量，不改变结论、不造成返工

【输出格式】
## 总体判断（一到两句）
## 发现（按严重度排序）
   每条：**[严重度] 标题** / 位置 / 问题 / 依据（技术依据，非空泛）/ 建议（含代价）
## 做得对的地方（简短，不要客套）
## 我不确定的地方（明确列出你没把握的判断）
```

## 六个视角的专属审查点

**领域实现**（RAG / 前端 / 具体技术栈）
文档数量与质量是否支撑场景 · 元数据 schema 能否真正落地到所选平台 · 引用可溯源的实现路径 · 指标如何度量、是否可达 · 该技术栈的已知能力边界 · 多租户/多业务域的内容串扰 · 版本与时效管理

**状态与编排**
拓扑边界与状态污染 · 路由分级是否真的可行（尤其需要训练数据的那一级）· 槽位管理与追问上限 · 写操作确认的状态机（令牌生成校验、超时、拒绝回退、重放语义）· 两套编排系统的职责边界是否真划得清 · 目标模型的工具调用可靠性 · 错误处理与降级完整性

**数据与后端**
建模是否贴近真实业务 · 关键分析场景的数据模型撑不撑得住 · 数据量与**分布**是否支撑评测 · 审计表字段完备性 · 幂等与事务边界 · 单实例承载多类负载的合理性 · 权限隔离的实际可行性 · API 契约（端点、错误模型、分页、枚举 description）

**环境与运维**
资源核算逐组件复核（要求给具体数字）· 硬约束在实际开发中可操作吗 · 网络与隧道稳定性 · 启动参数是否给够指导 · 可观测性缺什么 · 备份策略 · **演示当天的失败概率** · CI 可行性

**安全与合规**
不可信输入与特权同域 · 二次确认能否防绕过 · 审计完备性与防篡改 · 越权与数据权限 · 数据出边界的合规影响 · 脱敏方案是否真的不可回溯 · 集成路径的凭据处理 · 取证产物的敏感信息
→ 额外要求：每条标注 **「PoC 阶段必须解决」/「规模化落地前解决」**

**交付管理**
逐阶段拆解重估工期 · 单人/小团队的系统性风险 · 阶段依赖与能否前置降险 · 验收指标的可达性与**可度量性** · 样本量的统计意义 · 对比结论的说服力 · 交付物清单是否完整对应立项要求 · 收敛机制会不会流于形式 · **必须砍时砍什么** · 报告能否支撑立项决策
→ 额外要求输出一节 **「工期重估」**：自己的逐阶段人天与总计，并说明差异来源

## 派发机制

- **同一条消息里发出全部派发**，并行且互不知情
- 放**后台**，不阻塞等待
- 后派发的可以带上「已知的其他评审发现」，避免重复劳动——但**不要给他们前面评审者的结论细节**，否则会污染独立性
- 掉线的重派时，在指令里**强化查证次数限制**（掉线主因就是无限重试外部查证）

## 收到结论后

先做**归一化**再计数收敛——不同评审者会用不同词汇描述同一缺陷。
然后按 `SKILL.md` 第二节做裁决：会导致返工的、与实测证据冲突的、断言"能力不存在"的，**自己验证一遍再采纳**。
