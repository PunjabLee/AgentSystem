## 1.2 P0 推翻的三个既有判断

**① 型号：立项 brief 一直是对的**

brief 指定「Qwen3.8 系列 27B」，设计 v1.0 断言该型号不存在并改用 Qwen3-32B。**实际 `Qwen/Qwen3.8-27B` 真实存在**（↓345 万）。R1 风险登记了这一条，跨越八个版本才被执行核实。

连带发现：Qwen3.8 是**混合注意力架构**（48 层线性 + 16 层全注意力），真实 KV/token = 64 KiB 而非按常规稠密模型算的 256 KiB——**此前显存测算高估 4 倍**。

**② 内存：16GB 扛不住 Dify 的担忧被证伪**

| | 估算 | 实测 |
|---|---|---|
| 我的初版 | 3.5 GiB | — |
| DevOps 评审重估 | 3.6–7.0 GiB，中位 5 GiB | — |
| **14 容器实测** | — | **2.25 GiB** / Docker 分配 7.75 GiB |

评审建议的内存优化（`CELERY_WORKER_AMOUNT=1`、去掉 collaboration）**现已无必要**。

**③ 按 BU 拆知识库文件的收益低于预期**

P0-6 刻意保留三 BU 混编，结果检索与生成**仍能正确区分三个事业部**。机制⑤ 的真实价值在**权限隔离**（服务端强制注入 `bu_code` 过滤），不在防串答。

## 1.3 P0 暴露的、必须带入 P1 的三个坑

| 坑 | 后果 | P1 处置 |
|---|---|---|
| **PG 18 更改了 Docker 挂载约定** | 必须挂 `/var/lib/postgresql` 而非 17 时代的 `/var/lib/postgresql/data`，否则容器起不来 | 写入部署文档 |
| **跨 Debian 版本换镜像 → collation 全面失配** | 该问题**三次出现**，第三次卡死了全部 `CREATE DATABASE`，因 `template1` 未修 | 部署文档必须列出**含 `template1` 的完整修复清单** |
| **配置中同一凭据的多份副本会静默分叉** | `CELERY_BROKER_URL` 内嵌了第二份 Redis 口令，与 `REDIS_PASSWORD` 分叉，worker 失联 **24 小时**、重试 25 次，文档上传静默 500 | **升级为 CI 机械检查**（见 §2.4） |

# 第三部分 · D1 资源申请（AutoDL 实例）

## 3.1 申请什么

| 用途 | 卡型 | 显存 | 系统内存 | 数据盘 | 镜像要求 |
|---|---|---|---|---|---|
| **M1 经济档** | RTX 5090 | 32 GB | ≥ 64 GB | 100 GB | **CUDA ≥ 12.8 / 驱动 ≥ 570** |
| **M2 旗舰档** | A100 | 80 GB | ≥ 64 GB | 150 GB | CUDA ≥ 12.1 |

**若两档共用一台实例，数据盘需 200 GB。**

> 🔴 **5090 是 Blackwell 架构（sm120），镜像 CUDA 必须 ≥ 12.8。** 12.4 及更早的镜像编译不出 sm120 内核，vLLM 启动即失败——这是选错镜像后最耗时的排查之一。

## 3.2 为什么必须要

**M1/M2 是「自建」这一臂的唯一来源。** 立项 brief 明文要求：

> 输出**本地 / 云端双模型方案对比结论**与选型建议

当前四个对比维度的证据状况：

| 维度 | 无 D1 时 | 有 D1 时 |
|---|---|---|
| 准确率 | 只有托管档，无对照 | M1 vs M2 vs M3 vs M4 |
| 延迟 | 同上 | 同上 |
| **成本** | **只有 API 单价，无自建 TCO** | 可建参数化 TCO 模型 |
| 数据安全性 | 已声明无实测证据（AutoDL 属第三方） | 同左 |

**没有 D1，PoC 报告的核心结论「该自建还是该采购」拿不出任何自建侧数据。**

## 3.4 时间要求

**建议现在就申请，不要等 P1 做完。**

理由：D1 的瓶颈是**外部资源与前置周期**，不是我方工时——

```
开实例 → 下载 51.7 GB 权重 → vLLM 调参 → tool_calls 验证

```

而 P1–P4 的功能开发**不依赖 D1**（M0 + M3 + M4 三档已能跑通全链路）。所以正确的调度是**并行**：P1 立刻开工，D1 同步申请。**等 P1 做完再申请，就把等待时间串进了关键路径。**

**最晚到位时间：P2 结束（约第 6 周）。**

原写「P5 开工前」是错的——那时才发现缺失，M1/M2 已无从补做。新死线到点未到位**自动触发砍范围**（[设计文档 §15.3](superpowers/specs/2026-08-28-enterprise-ai-poc-design.md)），无需再开会决策：

- **仅一种卡** → 保留 A100（M2，准确率上限基准，比经济档更不可替代）
- **完全未到位** → 自建侧整体作废（约省 4 人天），**「本地/云端双方案对比」降级为「不同托管方案横向对比」**，须书面告知立项方

## 3.6 D1 已开通 · 无卡模式窗口的用法（2026-08-30 更新）

D1 已按规格开通，当前为**无卡模式**（CPU-only，不计 GPU 费用）。

**这正是 §3.3 所说的最优下载窗口。** 建议在切换到 GPU 模式前，先在无卡模式下完成全部权重下载：

| 档 | 仓库 | 体积 |
|---|---|---|
| M1 | `unsloth/Qwen3.8-27B-NVFP4` | 21.8 GiB |
| M2 | `Qwen/Qwen3.8-27B` | 51.7 GiB |

合计 **73.5 GiB**。按国内网络下载耗时可能 1–3 小时——**用无卡模式做这件事，可省下等量的 GPU 计费**。走 ModelScope 而非 HuggingFace。

### 需要提供的接入信息

要在无卡模式窗口内启动下载，需 §3.5 的前两项：

1. **SSH 地址与端口**
2. **SSH 公钥是否已上传**（推荐）

凭据请按宪法第七条自行写入 `.env`，不经对话传递：

```bash
cat >> .env <<'EOT'
AUTODL_SSH_HOST=你的实例地址
AUTODL_SSH_PORT=你的端口
EOT
```

**同时需在 P0-7 验证的一个假设**：AutoDL 实例**关机再开机后，SSH 地址与端口是否变化**。当前设计默认它不变（`.env` 存一份即可）。若会变，隧道脚本必须参数化、每次开机重读。**15 分钟即可验证，假设错了会在演示当天爆炸。**
