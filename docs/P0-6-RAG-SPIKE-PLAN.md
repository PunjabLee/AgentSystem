## 1. 这一步在验什么

**验的是「引用可溯源」这条链能否走通，不是准确率达标。** P0-6 是可行性验证，不是评测。

链条有四个环节，任一环断裂则 §8 的检索路径需要重做：

```
① Dify 检索 API 能否按元数据过滤        →  断则四维过滤落不了地
② 召回的 chunk 是否包含答案所需事实      →  断则切块策略错
③ 返回的元数据能否定位回原文具体位置      →  断则引用无法构造（宪法第九条）
④ 答案中的事实能否对应到引用 chunk       →  断则「引用准确率」不可度量
```

环节 ③ 是宪法第九条的直接要求；环节 ④ 是 RAG 评审指出的缺口——**③ 只保证「引用指向真实 segment」，保证不了「引用与答案内容一致」**。

## 2. 测试语料

**唯一文档**：`corpus/06-色差与等级判定标准.md`（QC-STD-006 v3.2）

选它是因为它是 8 份规划文档中最难的一份，同时具备四个致命特征：

| 特征 | 为什么难 |
|---|---|
| **双 BU 混编** | §2 印染、§3 建陶结构高度相似，`bu_code` 只能标 `ALL`——RAG 评审指出的「文档级过滤在此失效」正是这里 |
| **两个同构阈值表格** | 都是「优等品/一等品/合格品」三档，极易混淆 |
| **例外条款内嵌** | 例外与主条款在同一小节，测切块是否把它们切散 |
| **同名指标不同值** | 优等品 ΔE 阈值：印染 ≤1.0、建陶 ≤0.8 |

用简单文档问简单问题，100% 通过说明不了任何事。

## 3. 五个问题及其冻结判据

每题核对三层，**三层全过才算该题通过**：

- **(a) 检索层**：召回的 chunk 中确实包含回答所需的事实
- **(b) 定位层**：引用的 `document_name` / `segment_id` 能反查到原文的具体位置
- **(c) 一致层**：答案中每个关键事实（数值、阈值、条款）都能在引用 chunk 原文中逐字或语义等价找到

### Q1 · 单跳事实（基础能力）

> 印染事业部优等品的 ΔE 阈值是多少？

| 层 | 通过判据 |
|---|---|
| (a) | 召回 chunk 含 §2.1 的阈值表格或其等价文本 |
| (b) | 引用能定位到 §2.1 |
| (c) | 答案给出 **≤ 1.0**，且该值出现在引用 chunk 中 |

**失败信号**：答成 0.8（建陶的值）→ 表格混淆；答对但引用指向 §3.1 → 引用与答案不一致（(c) 不通过）。

### Q2 · 跨 BU 歧义（最高危）

> 优等品怎么判定？

**未指明事业部，而两个 BU 的阈值不同。**

| 层 | 通过判据 |
|---|---|
| (a) | 召回同时含 §2.1 与 §3.1，或系统主动追问 |
| (b) | 若作答，引用须同时指向两节 |
| (c) | **答案必须区分两个事业部**，或**主动追问是哪个 BU** |

**失败信号**：只给一个数值而不说明是哪个 BU —— 这是本次验证最需要暴露的失效模式。

### Q3 · 例外条款（切块质量）

> 印染优等品的色差阈值有没有不适用的情况？

| 层 | 通过判据 |
|---|---|
| (a) | 召回 chunk 含 §2.1 的「例外情形」段 |
| (b) | 引用定位到 §2.1 |
| (c) | 答案提到**深色系（L\* < 30）放宽至 1.5**，且提到**「色差从严」标注的批次不适用该放宽** |

**失败信号**：只答放宽、漏掉「不适用」的二次例外 → 例外条款被切散。

### Q4 · 表格取值（表格可检索性）

> 建陶一等品的平整度偏差上限是多少？

| 层 | 通过判据 |
|---|---|
| (a) | 召回 chunk 含 §3.1 表格 |
| (b) | 引用定位到 §3.1 |
| (c) | 答案给出 **≤ 0.5 mm/m**，且该值出现在引用 chunk 中 |

**失败信号**：答不出或答成印染的色牢度值 → 表格切块后语义丢失。

### Q5 · 无答案拒答（幻觉检测）

> 产品包装破损应该怎么索赔？

**文档中不存在该内容**（仅 §5 提及色差异议，与包装破损无关）。

| 层 | 通过判据 |
|---|---|
| (c) | 明确说明文档中未涵盖该内容，**不得编造赔偿流程或金额** |

**失败信号**：编造索赔条款，或强行引用 §5 争议处理充数。

## 4. 结论分级（执行前冻结）

| 结论 | 判据 | 后果 |
|---|---|---|
| 🔴 **不可行** | 环节 ③ 断裂——返回的元数据不足以定位回原文 | **§8 检索路径重做**，P3 的 2.0 人天作废 |
| 🟡 **可行但需调整** | ③ 通过，但 ①②④ 中有环节不达预期 | 调切块策略 / 元数据 schema / 加标题链前缀，P3 内消化 |
| ✅ **可行** | 四个环节均通过，且 5 题中 ≥4 题三层全过 | 按现设计推进 |

**Q2 单独具有否决权**：若 Q2 失败（不区分 BU 直接给单一数值），即使其余四题全过，也判为 🟡——因为跨 BU 串答会直接击穿 §14 的「跨 BU 歧义」边界用例。

## 5. 顺带确定的两项设计空白

## 6. 环境配置（执行时填写实际值）

| 项 | 计划值 |
|---|---|
| embedding | `qwen3-embedding:0.6b`（Ollama，1024 维，32K 上下文） |
| rerank | 本轮不启用，用 Dify `weighted_score` 模式 |
| 分段模式 | 父子分段（Parent-child），父块按 H2/H3 小节 |
| 检索模式 | hybrid |
| Top-K | 待定，执行时记录 |
| 向量后端 | pgvector 0.8.6（`agentsystem-pg` 的 `dify` 库） |

多模态 embedding（WeMM-Embedding-2B + Xinference）**转入低优先级待办 P0-9**，不阻塞本轮。理由：Ollama 的 `/api/embed` 不接受图片输入（`EmbedRequest` 无 `Images` 字段），走 Ollama 路径拿不到多模态能力；而 P0-6 验的是引用可溯源，纯文本即可验完整条链。
